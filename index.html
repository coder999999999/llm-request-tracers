Same request, two designs

The short version of what the tracers show.

llama.cppvLLM
Shape One process. HTTP threads hand work to a single inference thread. Two processes. An API process and an EngineCore that owns the GPU, talking over ZMQ.
Batching A fixed number of slots (--parallel), one llama_decode per tick. A token budget per step. Prefill and decode share one flat batch.
Reusing a prompt Picks the slot whose cache shares the longest prefix. Reuses any matching 16-token block, even from another request.
Out of memory Retries with a smaller batch. Preempts a running request and recomputes it later.

Each repo was read at a pinned commit (llama.cpp 2ca15f5, vLLM 1388100) with Claude, and every box links to its source line. It's simplified and probably wrong in places. Corrections welcome as issues.
